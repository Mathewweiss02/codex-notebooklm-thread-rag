# Factors

| Factor | Why it matters | Current evidence | Candidate bottleneck | Missing evidence | Next move |
| --- | --- | --- | --- | --- | --- |
| Retrieval accuracy | Wrong task retrieval defeats the system | Fresh 24-case corpus: 23/24 raw unique Top-1 and 24/24 hybrid Top-1 | Validation bottleneck | Repeatability across corpus growth and upstream versions | Preserve the benchmark and add canary runs |
| Candidate recall | Local reranking cannot recover a task NotebookLM never cites | Fresh 24-case corpus: 24/24 semantic candidate recall | Architecture bottleneck | Recall under multi-notebook routing | Keep 100% as the router stop gate |
| Freshness | A task unavailable for an hour is not truly live | QuietMinutes is 60; one active task was deferred | Throughput bottleneck | Churn, rate-limit, and retrieval effects at shorter gates | Compare 60/15/5 minute profiles |
| Coverage | A new task must not vanish from retrieval | Capacity-aware enrollment transaction is enabled live for both 130-task notebooks | Coordination bottleneck | Behavior at the first shard boundary | Add sticky shard ownership before multi-notebook growth |
| Source capacity | Notebook limits define the scaling boundary | 2x/5x/10x simulation preserves reserve but full-replan churn reaches 64.62%/83.08% | Architecture bottleneck | Selective-router recall and sticky-assignment migration | Compare sticky ownership plus local routing |
| Conversation integrity | Human CLI history must survive automation | Separate chat/retrieval notebooks passed an unchanged-ID/unchanged-turn live test | Architecture bottleneck | Long-running human conversation behavior | Keep role policy and regression canary |
| Runner reliability | Old success cannot imply current health | Doctor validates age/status; interrupted uploads resume; live runners pass | Validation bottleneck | Recovery behavior across reboot and logout | Add reboot/logout canaries |
| Auth truth | Exit code 0 can still mean auth error | JSON status is parsed everywhere; passive live checks pass | Tooling bottleneck | Expiry and revoked-cookie canaries | Add scheduled auth-failure fixtures |
| Source integrity | Wrong content under a familiar title creates silent corruption | Titles are collision-resistant; live content hash is not verified | Validation bottleneck | Upstream source text/hash inspection support | Add content-addressed evidence experiment |
| Reconciliation | Extra sources can pollute answers | Missing expected sources are rejected; extras are not | Validation bottleneck | Behavior in shared versus dedicated notebooks | Strict dedicated-notebook mode |
| Parsing robustness | One giant record can block a task | Image-heavy record fixes pass; 8 MiB visible-line ceiling remains | Throughput bottleneck | Real maximum record distribution and streaming alternatives | Corpus scan plus oversized fixture experiment |
| Data lifecycle | Unbounded files create clutter and leakage surface | Guarded live retention removed obsolete artifacts while protecting current/previous lineage | Tooling bottleneck | Long-term retention trend | Aggregate retention metrics |
| Observability | Operations need truth without opening raw files | JSON reports exist but no summary trends or SLOs | Knowledge bottleneck | Metric aggregation and failure budget | Add status/metrics report and radar inputs |
| Privacy modes | Remote credentials must never leak; local recall may need more context | Projection sanitizer is stronger than query sanitizer | Architecture bottleneck | Value of a local-only trust mode | Share remote redaction contract; test local-only mode later |
| Reproducibility | A pinned top-level package is not a full environment | Complete uv lock, hash export, exact CI audit, and zero known vulnerabilities | Tooling bottleneck | Cross-version canary coverage | Maintain Dependabot cooldown and release canaries |
| Upstream resilience | Unofficial API changes can break auth/chat/sources | v0.8.0 works now | Knowledge bottleneck | Compatibility with future releases and rollback time | Add upstream canary matrix |
| Multi-device behavior | Duplicate projections and ownership can corrupt retrieval | Device namespaces exist; full collision/failover behavior unproven | Coordination bottleneck | Simultaneous device test | Design ownership and duplicate experiment |
| Operability/CLI UX | The user wants CLI as the main NotebookLM surface | CLI is installed and documented as primary | Tooling bottleneck | One-command enroll/status/search/recover workflow | Add CLI-first command surface |
| Cost/rate limits | Free service limits can change feasible update frequency | Initial upload took about 28 minutes | Throughput bottleneck | API call count and throttle envelope | Instrument calls/durations and load-test gently |
| Maintainability | Many scripts and duplicated contracts increase drift | PowerShell, Python, and Node share configuration implicitly | Architecture bottleneck | Stable schemas and common validation layer | Add config schema and cross-runtime contract tests |
